# spoons-mcp

Client and command-line tool for the unofficial API behind Wetherspoon's order-and-pay app. `spoons-api-client` speaks the API; the `spoons` binary (crate `spoons-mcp`) dumps pubs and menus into `data/`, extracts prices and ranks pubs into tiers by what a round costs. The README explains the API's quirks. The only thing published is the `spoons` binary, attached to GitHub releases; there are no crates.io packages or images.

## Git

- Work in PRs; never push to main. PRs are squashed; merge main into a branch rather than rebasing.
- Never push tags.
- Commits are signed.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; to correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`, or the Release workflow in Actions) opens a `release-vX.Y.Z` PR that bumps the workspace version in `Cargo.toml` and `Cargo.lock` and turns the unreleased fragments into that version. Merging it is the release: CD sees the version change, builds the binaries and creates the tag and GitHub release with the changelog section as notes. Never tag by hand. A failed release is retried by running CI/CD manually on main. Both workflows need the `RELEASE_TOKEN` secret, since a PR or release made with the workflow token starts no workflows.

## Check

```sh
just check   # actionlint, Cargo.lock drift, fmt --check, clippy -D warnings, tests (offline)
just fast    # the seconds-long subset; the pre-push hook runs it
just fmt
```

`data/` and `recon/` are gitignored working output; tests never call the live API.

## CI

`.github/workflows/ci-cd.yml` ends in one job, `Checks`, which is the only status the ruleset requires; it passes when every other job succeeded or was skipped. A job is skipped when the change does not touch its domain, so a docs-only or changelog-only change runs no Rust job. The `changes` job decides the domains from the diff: a pull request against its base, a push against the last main commit whose run passed, and a manual run, or any diff it cannot work out, runs everything. Markdown never counts, and `.github/` counts for every domain.

To add a domain, give `changes` an output and an allowlist of the paths that reach it, gate the new jobs with `if: needs.changes.outputs.<domain> == 'true'`, and add them to `Checks`'s `needs`. A job with no domain (like `Changelog` and `Actionlint`) runs on every change. `Security Audit` runs on every push to main, since an advisory can appear without the code changing, and on pull requests only when dependencies change. An advisory that cannot yet be fixed is acknowledged in `.cargo/audit.toml` with the reason and what would let it be dropped.
